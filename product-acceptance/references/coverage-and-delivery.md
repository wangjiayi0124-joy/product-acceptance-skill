# 覆盖与交付规范

## 一、按需求选择覆盖维度

从需求证据中筛选下列维度；仅保留与功能有关者，并把选择理由写入用例条件。

| 维度 | 何时纳入 | 典型检查点 |
| --- | --- | --- |
| 角色与权限 | 存在身份、可见范围、审批或配置权限 | 未登录、不同角色、越权、隐藏入口、直链访问 |
| 入口与路由 | 存在菜单、搜索、深链、回跳或多入口 | 进入、刷新、返回、前进、复制链接、空入口 |
| 业务主链路 | 用户完成一项目标有多个步骤 | 入口→选择/填写→确认→结果→可追溯状态 |
| 数据状态 | 列表、详情、筛选、表单或异步数据 | 有数据、无数据、边界数据、加载、重复提交、刷新后状态 |
| 规则与边界 | 有限制、计算、排序、时间、额度或校验 | 临界值、互斥条件、默认值、提示文案、禁止路径 |
| 异常与恢复 | 有失败提示、重试、取消、回退或中断可能 | 请求失败、网络中断、无权限、重复点击、返回后恢复 |
| 外部依赖/跳转 | 调用第三方、端内外切换、下载或外链 | 目标、授权、返回路径、不可用时的提示与降级 |
| 兼容与迁移 | 有多端、多版本、旧数据/旧链接或发布环境 | 浏览器/设备、旧入口、环境标识、回归与数据兼容 |
| 可观测性 | 明确要求埋点、日志、通知、审计或性能 | 事件、参数、通知、审计记录、耗时阈值 |

常用链路视角：`入口 → 前置判断 → 核心动作 → 结果反馈 → 后续状态/恢复`。每个关键分支均要有明确的预期来源。

## 二、优先级与严重级

若需求没有既定标准，使用以下默认约定并在清单开头注明：

| 级别 | 判断 |
| --- | --- |
| P0 | 核心目标无法完成、严重越权、数据损坏或安全风险 |
| P1 | 关键链路不可用或结果错误，有明确用户影响 |
| P2 | 非核心功能错误、体验明显受损、存在替代路径 |
| P3 | 轻微文案、样式或低频体验问题 |

严重级评估基于真实影响和复现范围，不因“测试环境”自动降级；环境不确定时先标阻塞。

## 三、状态与证据边界

| 状态 | 适用边界 | 必填信息 |
| --- | --- | --- |
| 通过 | 已执行且符合明确预期 | 实际结果、条件、证据或操作记录 |
| 不通过 | 已具备条件但违背明确预期 | 复现步骤、实际结果、问题描述、严重级、证据 |
| 阻塞 | 无法安全或有效判断 | 阻塞原因、缺少条件、建议下一步 |
| 待定 | 计划存在但本轮未测 | 待补测范围、原因 |

需求本身没有给出判断标准时，不要将“感觉不对”记为不通过；提出待确认问题，获得答案后补测或更新结论。

## 四、可读的 CSV 与办公文档/表格

### CSV

- 一行一个用例；列名稳定、可直接导入。
- 以 UTF-8 编码；含逗号、换行或引号的字段必须正确引用和转义。
- 长文本采用短句。可在同一单元格内使用换行区分“问题描述/影响/阻塞条件”，不要把预期、实际、复现步骤揉成一段。
- 始终保留用例 ID，方便清单和问题列表相互定位。

### 目标办公产品的原生表格

- 当用户指定钉钉、飞书、金山或其他办公产品时，使用该产品的原生表格能力，不以 Markdown 竖线文本代替。未指定时，默认交付通用 CSV；不要自行假定目标产品。
- 顶部对齐全部单元格；长文本列优先扩宽。默认可从：复现步骤约 160px、实际结果约 180px、问题描述约 280px 起步，再按内容调整。
- 用例 ID、状态、优先级等短字段保持窄列；不要挤压问题描述列。
- 问题描述以标签开头并自然断句；同格多段时使用段落而非密集长句。
- 写入后抽查表头、长问题描述、状态列和末行，确认未截断、未错列、换行可读。
